# Demo 4 — Document Processing

**Label: Demo — fictional data. This is not client work.**

Fictional supplier invoices and intake forms for fictional Harbor Outdoor Gear are extracted to a sheet, field by field, with a confidence score per field. Clean documents flow through; mismatched totals and missing fields go to a human exception queue. Nothing is silently corrected.

## How to run

```bash
cd demo4-document-processing
python3 doc_processor.py
python3 -m unittest test_doc_processor.py -v
```

Outputs:
- `outputs/extraction_log.csv` — every document, extracted fields, per-field confidence, validation result, status, destination
- `outputs/summary.json` — counts by status and document IDs per status
- `outputs/before_after.md` — raw extraction vs. final sheet status

## Pipeline

Mock document (extracted text in `mock_documents/`, extracted fields in `documents_fictional.json`) → validate in code → route Clean to sheet / Exception to human queue

Validation rules, as code:
- V1 total = subtotal + tax, within $0.01
- V2 line items sum to subtotal, within $0.01
- V3 date is a valid YYYY-MM-DD date
- V4 PO number present and not a duplicate of an earlier document
- V5 no extracted field has confidence below 0.70

## Walkthrough — three documents to show a buyer

- **DOC-01 — Clean:** Alpine Gear Supply, PO-1001, subtotal $540.00 + tax $43.20 = total $583.20, line items sum to $540.00. → Sheet (Clean).
- **DOC-09 — Exception, field = total:** subtotal $500.00 + tax $40.00 should be $540.00, but the stated total is $560.00. → Human exception queue, total left as $560.00, never auto-corrected.
- **DOC-10 — Exception, field = po_number:** PO number is missing. → Human exception queue, reason `po_missing`.

## Acceptance criteria (checked by the tests)

- All 10 documents logged, in input order
- Distribution: 8 Clean, 2 Exception (DOC-09, DOC-10)
- Both exceptions land in the exception queue, neither is auto-corrected
- No clean document is sent to the exception queue for a reason outside the validation rules
- Duplicate PO and invalid date are detected (unit tests)

## Honest limitation

PDF → text extraction and LLM/structured extraction are not built here — the demo starts from the extracted JSON so validation is fully reproducible. Do not list PDF extraction or LLM extraction as built experience from this demo alone, and do not claim an accuracy percentage beyond what this 10-document test set actually shows.
